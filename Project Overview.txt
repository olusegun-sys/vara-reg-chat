## 1. What We're Building

A **Retrieval-Augmented Generation (RAG) chat** for querying global regulatory rulebooks. The user picks a jurisdiction, asks a question, and the system retrieves the most relevant chunks from FAISS, passes them to an LLM with strict citation rules, and returns a grounded answer.

**If the answer isn't in the internal corpus, the system searches the live web via Tavily — restricted to authoritative sources (official regulators + established press).** If the web search returns nothing trusted, the app *honestly refuses* rather than hallucinating a citation.

**Why it exists:** Banks, fintechs, and VASPs drown in sprawling regulations (VARA / FCA / SEC / EU). An uncited answer is worthless in compliance. This tool answers only from the document or live web, cites every claim, and refuses when no authoritative source exists.

**Design goal from day one:** multi-jurisdiction architecture. Adding a new regulator must require zero backend code changes — just drop PDFs, tag the jurisdiction, `ingest.py --reset`, commit the new index, push.

## 4. Architecture & Design Decisions (Validated)

1. **SSE streaming** — `/api/chat/stream` yields Server-Sent Events; the frontend buffers on `\n\n` to prevent JSON truncation.
2. **Cloud embeddings (Cohere)** — replaced local PyTorch to kill the Render 512MB OOM class of bugs.
3. **Per-browser privacy (Supabase)** — unique `vara_browser_id` in `localStorage`. Terry gets a clean slate when he opens the link.
4. **Conversational memory** — frontend sends a smart window (first 2 + last 8 messages); backend injects into the prompt for follow-ups.
5. **Jurisdiction-aware query rewriter** — cheap LLM call rewrites vague questions into keyword searches. **Deterministic post-processor (`_postprocess_rewrite`) sanitizes output** — detects truncation, strips cross-cutting service words.
6. **Multi-jurisdiction system prompt** — the LLM is told which jurisdiction it is answering for. Cross-contamination is explicitly forbidden.
7. **🆕 Three-trigger web fallback (2026-11-05):**
   - **Trigger A:** out-of-scope regulator token detected in question (`fca|sec|mas|...`), from `config.OUT_OF_SCOPE_JURISDICTION_TOKENS`
   - **Trigger B:** FAISS best distance > `config.LOW_CONFIDENCE_DISTANCE` (= 1.15)
   - **Trigger C (post-generation retry):** the LLM's answer contains a refusal phrase from `config.REFUSAL_PATTERNS` → silently retries once with web search
8. **🆕 Domain-restricted web search:** web results are **filtered to `config.TRUSTED_DOMAINS` (primary regulators + established press)**. Untrusted sources (LinkedIn, Medium, blogs, Instagram) are dropped silently. Each result carries an `authority_tier` label (`primary` / `press`) used in citations.
9. **🆕 Honest refusal:** when both internal retrieval and whitelisted web search return nothing, the app returns an honest refusal message rather than fabricating a citation. The wording is: *"No authoritative source found for this question. This tool is scoped to regulatory and compliance topics..."*
10. **RAG eval harness (Phase 1 RSI)** — `eval/run_eval.py` runs a 10-question Golden Dataset against `/api/chat`. Validates retrieval and groundedness. Unicode normalizer handles `U+2011` smart-hyphen bug.
11. **Premium UI/UX** — near-black DeepSeek-style palette. Tables render natively. Source chips are full-width stacked cards.
12. **Custom jurisdiction popover** — replaced native `<select>` with a custom React popover.
13. **VARA footer sanitizer** — `clean_vara_pdf_text()` strips bilingual page footers from VARA PDFs. Guarded by `_is_vara_document()` so it doesn't strip EU Article numbers.
14. **FAISS in-memory cache** — caches `_INDEX` and `_METADATA` at module level; saves ~530ms per query.
15. **Git & deploy strategy** — FAISS index files are committed to git (removed from `.gitignore`) so Render deploys with vectors in place.

## 12. 🟡 KNOWN GAP: EU Article 50 Retrieval (Question #7)

**Symptom:** Eval question #7 (`What are the transparency obligations for AI systems that interact with humans?`) fails on keyword match (`expected any of 'transparen,article 50'`).

**Diagnosis (confirmed via `/debug-search`):**
- `fallback_triggered: false` — the fallback is NOT the culprit.
- `best_internal_distance: 0.796` — FAISS is *confident* it found a match.
- **But all 8 returned chunks are recitals or editorial paragraphs, not Article 50 itself.** Example chunks returned:
  - "(33) When supervising and enforcing obligations..." (recital)
  - "(37) The requirements for high-risk AI systems laid down..." (recital)
  - "Article 110 Amendment to Directive (EU) 2020/1828..." (wrong article)

**Root cause:** the EU AI Act PDF has front-loaded recitals (numbered (1)–(180)) whose embeddings are structurally similar to Article 50. FAISS ranks them higher than Article 50's actual text because the recitals discuss transparency more frequently than the article itself.

**Fix options (not applied yet):**

- **Option A — Rewriter hint (fast, ~30 min):** add a `QUERY_HINT_MAP` in `config.py` that detects "Article 50" / "transparency obligations" queries and prepends an exact-match hint like `"Article 50 transparency obligations for AI systems that interact with natural persons"`. Plus a `REWRITER_PROMPT` addition: *"When the user asks about a specific Article, preserve the exact article title from the Act."*
- **Option B — Re-ingest the EU AI Act PDF with Article-aware chunking (slow, ~30 min + 15 min ingest):** add a pre-processor that splits the PDF on "Article N" boundaries so each article is its own clean chunk. Requires `ingest.py --reset`, FAISS re-commit, Render redeploy, full eval re-run.
- **Option C — Hybrid retrieval (biggest effort, ~2 hours):** after FAISS, if a specific article is named in the query, do a keyword search for that article string over all metadata and merge. Best long-term, not tonight.

**Recommendation:** apply Option A first. If it fails, escalate to Option B in a calm session (not before a demo). **Do not roll back the fallback fix to fix this** — the two are unrelated.
