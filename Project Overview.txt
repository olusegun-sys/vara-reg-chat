## 1. What We're Building

A **Retrieval-Augmented Generation (RAG) chat** for querying global regulatory rulebooks. The user picks a jurisdiction, asks a question, and the system retrieves the most relevant chunks from FAISS, passes them to an LLM with strict citation rules, and returns a grounded answer. If the answer isn't in the internal corpus (or the jurisdiction isn't ingested yet), it **falls back to a Tavily live web search** and synthesizes an answer with clickable web references.

**Why it exists:** Banks, fintechs, and VASPs drown in sprawling regulations (VARA / FCA / SEC / EU). An uncited answer is worthless in compliance. This tool answers only from the document or live web, cites every claim, and refuses when the answer isn't found.

**Design goal from day one:** multi-jurisdiction architecture. Adding a new regulator (CBUAE, DFSA, CBN, FCA, SEC) must require zero backend code changes — just drop PDFs, tag the jurisdiction, `ingest.py --reset`, commit the new index, push.

## 4. Architecture & Design Decisions (Validated)

1. **SSE streaming** — `/api/chat/stream` yields Server-Sent Events; the frontend buffers on `\n\n` to prevent JSON truncation.
2. **Cloud embeddings (Cohere)** — replaced local PyTorch to kill the Render 512MB OOM class of bugs.
3. **Per-browser privacy (Supabase)** — unique `vara_browser_id` in `localStorage`. Terry gets a clean slate when he opens the link.
4. **Conversational memory** — frontend sends a smart window (first 2 + last 8 messages); backend injects into the prompt for follow-ups.
5. **Jurisdiction-aware query rewriter** — cheap LLM call rewrites vague questions into keyword searches. **Deterministic post-processor (`_postprocess_rewrite`) sanitizes output** — detects truncation, strips cross-cutting service words (e.g. "custody") when the topic is service-agnostic (e.g. "AML").
6. **Multi-jurisdiction system prompt** — the LLM is told which jurisdiction it is answering for. Cross-contamination is explicitly forbidden. **Exception:** if retrieved chunks are labelled "Web Search Result", the LLM is permitted to answer for the actual jurisdiction the web hit came from.
7. **Tavily web fallback** — triggered by (a) regex detection of out-of-scope jurisdiction codes (`\b(fca|sec|...)\b`), or (b) empty FAISS result. Tavily chunks are formatted identically to FAISS chunks so the prompt and citation logic are unified.
8. **RAG eval harness (Phase 1 RSI)** — `eval/run_eval.py` runs a 10-question Golden Dataset against `/api/chat`. Validates retrieval (right document?) and groundedness (right keywords?). Unicode normalizer handles the `U+2011` smart-hyphen bug from LLM output.
9. **Premium UI/UX** — near-black DeepSeek-style palette. Tables render natively. Source chips are **full-width stacked cards** so long web URLs don't overflow.
10. **Custom jurisdiction popover** — replaced native `<select>` (ugly on mobile) with a custom React popover: checkmarks, hover states, two-line detail.
11. **VARA footer sanitizer** — `clean_vara_pdf_text()` strips bilingual page footers from VARA PDFs. **Guarded by `_is_vara_document()`** so it does not accidentally strip Article numbers from the EU AI Act.
12. **FAISS in-memory cache** — `retrieval.py` caches `_INDEX` and `_METADATA` at module level; saves ~530ms per query.
13. **Scroll-jump root-cause fix** — `App.jsx` uses `justSentRef` to prevent DB-driven reloads during streaming; `ChatWindow.jsx` scrolls the container directly.
14. **Git & deploy strategy** — the `.git` index was recovered after corruption. The **FAISS index files are committed to git** (removed from `.gitignore`) so Render deploys with vectors in place — this fixed the Render 500/CORS-misreported bug. **Consequence:** any future re-ingest means pushing a new ~10MB index.

## 8. API Contract (Live on Render)

### `POST /api/chat` (non-streaming, used by eval)
**Request:** `{"question":"...","jurisdiction":"EU","history":[]}`
**Response:**
```json
{
  "answer": "...",
  "sources": [{"page": 53, "section": "...", "document": "...", "source_url": "..."}],
  "session_id": "...",
  "model_used": "..."
}
```

### `POST /api/chat/stream` (streaming, used by frontend)
First SSE chunk: `{"type": "sources", "sources": [...]}`
Subsequent chunks: `{"type": "text", "text": "word "}`

### `GET /api/jurisdictions`
Returns the list of supported jurisdictions (`AE-Dubai`, `EU`) for the frontend dropdown.

### Other endpoints
`GET /api/health` — health + `vector_store_loaded` + `chunk_count`
`GET /api/warmup` — pre-load the embedding model (call 5 min before demo)
`POST /api/title` — generates a 3–5 word session title
